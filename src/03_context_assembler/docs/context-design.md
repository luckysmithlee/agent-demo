# 上下文组装设计

组装器接收指令、当前请求和按优先级排列的可选片段。调用方负责从历史消息、检索资料和工具结果中挑选证据，并按当前任务的重要性把高优先级内容放在前面。稳定规则和当前任务通过必填字段传入，原有空白也会保留。 [Context Assembler 实战 §3.9](https://my.feishu.cn/docx/VytpdGqFGoX0h2xuVPfckjpDnTg#doxcn8iv2vBxcylh6TEIQLo3OGc)

## 预算规则

1. 校验指令、当前请求和预算，先为两段必填文本计算字符数。两段之和超出总预算时抛出 `ValueError`。
2. 按输入顺序处理可选片段。`ContextFragment` 的内容只有超出单段限额时才截断。省略号 `…` 占用一个字符，限额为 1 时，超长内容只保留省略号。普通字符串直接参与总预算检查。
3. 将处理后的片段与剩余预算比较。放得下就收录，放不下就整段跳过，再检查下一段。

例如，总预算为 20，必填文本共占 12。第一段从 10 个字符截到 5 个，剩余 3 个字符。第二段长 4，整段跳过。第三段长 3，可以完整加入。结果的 `used_chars` 为 20，`truncated_indices` 为 `(0,)`，`skipped_indices` 为 `(1,)`。

## 调试与验证

- 用 `used_chars` 核对总占用，用 `skipped_indices` 定位完全未收录的原始片段，用 `truncated_indices` 定位被截断且已收录的原始片段。
- 若关键证据缺失，核对该片段在输入中的位置和处理时的剩余预算，再检查单段限额是否截掉了相关部分。回到调用方调整排序或提取更短的证据，最后检查实际发送给模型的内容。 [Context Debugging 清单 §3.11](https://my.feishu.cn/docx/VytpdGqFGoX0h2xuVPfckjpDnTg#doxcnDVuA5588PRriCu9z5MGfrd)
- 单元测试覆盖接口和边界，离线评测固定每个场景的预期收录结果和预算占用，便于对比规则改动。 [单元测试](../tests/test_assembler.py) · [评测样例](../evals/context_cases.jsonl)

## 接入模型

本实验按收录字符串的 Python 字符长度之和计算占用。实际调用时，先把结果渲染为消息，用目标模型的 Token 规则统计完整请求，把角色、分隔符和可能携带的工具定义计入输入，并为输出预留空间。来自检索或工具的文本应以数据身份渲染，保留它和稳定指令之间的来源边界。
