# 工具结果压缩设计

通用文本用 `compress_tool_result` 控制字符数。测试日志用 `compact_test_output` 保留失败线索，即使关键行出现在很长的输出中间。 [Tool Result 压缩实战 §3.10](https://my.feishu.cn/docx/VytpdGqFGoX0h2xuVPfckjpDnTg#doxcn17GsFleChsMu8fxwd6iwJf)

## 通用文本的字符预算

1. `text` 必须是字符串，`max_chars` 必须是正整数。空字符串有效，布尔值不属于有效预算。输入无效时抛出 `ValueError`。
2. 用 Python 的 `len` 计算 Unicode 码点数。内容放得下时原样返回，包括换行和空白。
3. 超过预算时先扣除截断标记的长度，标记记录原文字符数。剩余预算分给首尾，例如剩余 5 个字符时保留开头 3 个、结尾 2 个。标记与首尾各一个字符放不下时抛出 `ValueError`。

首尾截断会丢弃中间内容，适合希望同时看到开头和结尾的工具输出。

## 测试日志的结构化摘要

函数分别把 `stdout` 和 `stderr` 拆成行，先处理标准输出，再处理标准错误。每行做区分大小写的子串匹配，含有 `FAILED` 或 `ERROR` 就计入一次。

| 字段 | 内容 |
| --- | --- |
| `failure_count` | 全部命中行的数量。同一测试可能贡献多行。 |
| `important_lines` | 按上述顺序保留前 50 条命中行。 |
| `tail` | 所有输出的最后 80 行，可能包含已经收录的命中行。 |

两段输出的排列顺序按输入来源确定。关键词也可能出现在普通日志里，需要精确统计失败测试时应读取测试报告。按行保留也意味着单条日志很长时，摘要仍可能超过上下文预算。

## 加入模型上下文

把摘要序列化为 JSON 后，作为带来源的可选片段交给上下文组装器。调用方可以按任务优先级排列片段并设置单段字符上限。若下游需要解析完整 JSON，放不进预算时应跳过整段，避免截断后破坏格式。 [上下文组装实战](../../03_context_assembler/README.md)

可用单测验证原文保留、标记预算和失败行筛选，用评测样例检查不同输入下的预期结果。 [单元测试](../tests/test_compressor.py) [评测样例](../evals/compression_cases.jsonl)
