# 活动策划设计

本实战为 100 人的 AI Agent 交流会生成草案，整场预算上限为 2500 元。策划阶段先查看场地、政策和候选时间，再估算成本并交由主办方审批。示例用本地记录模拟查询结果，时段、场地名称和报价均为虚构。 [活动策划助手实战 §1.7](https://my.feishu.cn/docx/VytpdGqFGoX0h2xuVPfckjpDnTg#doxcnwd7PbQfkqTnAna92aBxNme)

## 证据与选择

`plan_meetup` 接收一个活动时段和该时段下的场地候选。每项候选记录名称、容量、场地费、档期可用性及来源。场地政策用于核实餐饮、设备和活动限制，本地规则示例只用结构化的容量、报价和档期数据做判断。

1. 容量、场地费或档期任一缺失时标为「待确认」。档期未回复用 `None` 表示，已占用用 `False` 表示。
2. 对证据齐全的场地，依次检查档期可用、容量至少 100 人、预计总额不超过 2500 元。先失败的条件决定判断结果。
3. 按输入顺序选第一个符合约束的场地作为拟选方案，保留全部候选及其判断和来源。

茶歇 600 元、物料 200 元、应急预留 300 元，合计 1100 元。总额按场地费加这三项计算，因此场地费最多为 1400 元。示例中的园区多功能厅档期可用，容量恰好 100 人，报价 1400 元，整场预计 2500 元，因此符合约束。报价 900 元但档期未回复的联合办公大厅仍标为「待确认」。

## 草案与审批

草案记录主题、人数、时间、场地候选、拟选场地、预算明细、议程、分工和风险。找到合格场地后，发布审批状态为「待审批」，输出四项拟提交的操作并停止。有权审批的主办方分别确认预订条件、日历时间与参与者、发布文案、通知对象与内容。程序只生成草案和待审批操作列表。

没有合格场地时，拟选场地标为「待确认」，场地费用保留为空，发布审批状态为「暂不提交」。补齐证据或调整候选后，可以用更新后的记录重新生成草案。 [单元测试](../tests/test_planner.py) · [离线评测样例](../evals/event_cases.jsonl)
